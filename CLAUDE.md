# claude-usage-bar

Claude Code usage limits in the macOS menu bar (SwiftBar), the GNOME top bar (Argos) and the
Windows / Linux tray. See README.md for the module map.

## Rules

- Edit `src/claude_usage/`, never `plugin/claude-usage.1m.py`: that file is generated by
  `tools/bundle.py` (run `./build.sh` or `python3 tools/bundle.py`) and committed. Installs from
  v1.2.x self-update by downloading exactly that path, so it must stay one self-contained file
  that starts with `#!/usr/bin/python3`, contains `VERSION = "X.Y.Z"` and compiles.
  `tests/test_bundle.py` runs the real v1.2.2 updater against it.
- Bundling rules (enforced by `tools/bundle.py`): sibling imports only as
  `from .module import name`; top-level names unique across all modules; no OS-specific work at
  import time (import `winreg`, `ctypes.windll`, `gi` inside functions).
- Python 3.9, standard library only: macOS runs it with Apple's `/usr/bin/python3` (3.9.6).
- User-facing text goes through `i18n.py` (Vietnamese default, English). Code, comments and docs
  are English.
- The SwiftBar output is pinned by `tests/golden/`. Regenerate with `UPDATE_GOLDEN=1` only for
  an intended change, and check the diff line by line first.
- Tests: `cd tests && /usr/bin/python3 -m unittest discover -p "test_*.py"`. CI runs them on
  macOS, Linux and Windows with Python 3.9.
- Release: bump `VERSION` in `src/claude_usage/config.py`, `./build.sh`, run the tests, tag
  `vX.Y.Z`, publish a GitHub release with the files from `dist/`. Every install self-updates to
  it, so never tag before the tests pass.
